# superkassa-desktop

Кассовое рабочее место: Compose Multiplatform и Material 3, одна сборка
под macOS, Windows, Linux и Android.

## Что это

Касса работает в процессе приложения: ядро `superkassa-core` подключено
библиотекой, и фискальная работа идёт в нём же, без отдельного узла и без
обращений по HTTP. Данные кассы лежат в каталоге данных рабочего места
(`~/.superkassa` у выпуска, `~/.superkassa-dev` при разработке, либо
`SUPERKASSA_HOME`).

Данные прежнего узла переносятся в кассу при первом запуске, до её
открытия. Перенос не удался — касса не открывается, а экран называет
причину и то, что делать: пустая касса выглядела бы потерянными сменами.

## Проверить кассу, ничего не собирая

Готовые установщики — на странице
[выпусков](https://github.com/texport/superkassa-desktop/releases).
Ставить Java и собирать что-либо не нужно: касса несёт всё с собой.

Для работы нужна сеть до сервиса приёма и до кабинета ОФД: адреса
приходят вместе с кассой при её заведении.

## Собрать самому

Приложению хватает открытых зависимостей:

```
./gradlew check                      # сборка и проверки
./gradlew :desktopApp:run            # запуск
./gradlew :androidApp:assembleDebug  # приложение для Android
```

Ядро — вместе с кодеком и протоколом, с которыми оно собрано, — сборка
берёт готовым из выпуска [superkassa-core](https://github.com/texport/superkassa-core/releases)
той версии, что в `gradle/libs.versions.toml` (`superkassa-core`): архив
`superkassa-core-maven-<версия>.zip` при первой сборке раскладывается
в локальный Maven. Собирать соседей из исходников не нужно.

Правка ядра вместе с кассой — версия `-SNAPSHOT` в каталоге и своя сборка
ядра: `(cd superkassa-core && ./gradlew publishToMavenLocal)`.

## Установщик для текущей системы

```
./gradlew :desktopApp:packageDistributionForCurrentOS
```

Кросс-сборки нет ни у `jlink`, ни у `jpackage`: `.msi` собирается только
на Windows, `.deb` — на Linux, `.dmg` — на macOS. Поэтому выпуски собирает
матрица из трёх систем, а не одна машина.

## Разделы

| Раздел | Что делает |
| --- | --- |
| Главная | Состояние кассы и смены, наличные, документы смены, печать и досылка |
| Продажа | Штрихкод и ручной ввод позиций, виды оплаты, принято и сдача |
| Возврат | Возврат по чеку-основанию из текущей смены |
| Деньги | Внесение и изъятие с остатком в ящике |
| История | Журнал за сутки с фискальными признаками |
| Очередь | Ждущие задачи отдельно от отправленных, повтор неудачных |
| Кассиры | Список, заведение, смена пина, удаление |
| Настройки | Выбор и заведение кассы, вход кассира, диагностика ОФД |

## Решения, которые стоит знать

**Состояние кассы видно всегда.** Шапка показывает состояние кассы, смену
и автономный режим на любом разделе: блокировку кассир должен увидеть до того,
как пробьёт чек, а не после.

**Отказ кассы и сбой разделены.** При отказе кассир правит чек, при сбое
зовёт обслуживание. Одинаковое сообщение увело бы его не туда, поэтому они
показаны по-разному.

**Пин живёт только в памяти.** Он даёт право на фискальные команды, и записывать
его на диск нельзя.

**Кредит и тара кассиру не предлагаются.** Эти виды оплаты объявлены устаревшими
и в схеме протокола 2.0.4 отсутствуют; касса такой чек отвергнет.

**Разделители в суммах заданы escape-последовательностями.** Неразрывный пробел
в исходнике неотличим от обычного, и однажды он уже развёл показ и разбор: сумма
`1 200` с обычным пробелом не принималась.
